# Release Notes: MCP-Pi Gateway v1.1.0

**Release Date:** September 2026  
**Type:** Minor Feature, Security Hardening, Anti-Spoofing & Appliance Management Release  
**Status:** PASS  

---

## 1. Summary

MCP-Pi Gateway `v1.1.0` introduces comprehensive end-to-end integration for cloud AI clients (ChatGPT / OpenAI Secure MCP Tunnel), cryptographic trust boundary enforcement with client ID anti-spoofing protection, secure high-level appliance management tools, zero-argument controlled reboot helper, conservative OS security update tracking, and tool catalog bump to version 3.

All security negative vectors remain strictly fail-closed, with zero arbitrary shell execution, zero open ingress ports, and strict loopback confinement.

---

## 2. Key Highlights & Changes Included

### Cryptographic Trust Boundary & Client ID Anti-Spoofing
- **Trust Boundary Enforcement**: Enforces pre-shared cryptographic Bearer token authentication on the Go MCP Streamable HTTP transport (`/mcp`) via `-auth-token-file /home/mcp-gateway/.config/mcp-gateway/tunnel-mcp.token`.
- **Anti-Spoofing Protection**:
  - Direct assertion of `X-MCP-Client-ID: chatgpt-main` without valid Bearer authentication is rejected fail-closed with `HTTP 401 Unauthorized: CLIENT_ID_SPOOFING_DENIED`.
  - Invalid Bearer tokens are rejected with `HTTP 401 Unauthorized: INVALID_AUTH_TOKEN`.
  - Anonymous callers receive empty tool catalog (`tools: []`) on discovery and `ANONYMOUS_CLIENT_DENIED` on calls.
  - Valid Bearer tokens establish authenticated context as `chatgpt-main` and receive authorized tools.

### SemVer v1.1.0 & Tool Catalog v3 Bump
- Bumped Gateway semantic version to `1.1.0` and Tool Catalog version to `3` across:
  - `manifest.json`
  - `compatibility.json`
  - `src/mcp_gateway/__init__.py`
  - `src/mcp_gateway/compatibility.py`
  - `src/mcp_gateway/lifecycle.py`
  - `mcp-adapter/main.go`
  - `mcp-adapter/server.go`
- Maintained core contracts:
  - `core_api_version`: 1
  - `bridge_api_version`: 1
  - `tool_catalog_version`: 3
  - `registry_schema_version`: 1
  - `mcp_protocol`: 2026-07-28 (with 2025-11-25 compatibility)
  - `go_sdk`: 1.7.0

### Appliance Administration Tools (5 High-Level Tools)
- Added 5 safe, scoped administrative tools governed by Gateway Policy:
  1. `gateway_status`: System metrics (RAM, zram, CPU load, temperature, storage, service status).
  2. `gateway_doctor`: 19-point system health, database integrity, permissions, and contract check.
  3. `gateway_backup`: Safe online SQLite backup generation.
  4. `gateway_maintenance`: Automated maintenance, backup rotation (keep 5), and security update audit.
  5. `gateway_reboot`: Controlled appliance reboot helper requiring explicit confirmation.

### Controlled Reboot Helper & Scoped Sudoers
- Created `/usr/local/bin/mcp-gateway-reboot` (`0755 root:root`):
  - Zero arguments allowed (fail-closed, rejects any parameters).
  - Syncs disk and invokes `/sbin/reboot`.
- Configured scoped sudoers rule `/etc/sudoers.d/020-mcp-gateway-reboot` (`0440 root:root`):
  - Grants `mcp-gateway ALL=(root) NOPASSWD: /usr/local/bin/mcp-gateway-reboot`.
  - User `mcp-gateway` maintains `sudo: NO` for any other command.

### Official OpenAI Secure MCP Tunnel Client
- Cross-compiled official `openai-tunnel-client` for ARMv6 (`armv6l` / BCM2835):
  - Upstream commit: `3b706ea54d0ad303c85d5ccd35633ae69405570b`.
  - Minimal 32-bit patch documented in `docs/tunnel-client-provenance.md` and archived in `patches/0001-fix-32bit-uint-overflow.patch`.
  - Deployed to `/usr/local/bin/openai-tunnel-client` (SHA256: `7788e773697dcade6f717aa42acf14cd8531282e5ee8b7822b2aace83c7fd6eb`).
  - Systemd service `openai-tunnel-client.service` with `ExecCondition` guard.
  - Zero open inbound ports required.

### Conservative OS Maintenance
- Configured `unattended-upgrades` on Debian 13 Trixie:
  - Security-only origins (`Debian-Security` & `Raspbian-Security`).
  - Blacklisted kernel, firmware, and bootloader packages.
  - Automatic reboot disabled (`Automatic-Reboot "false"`).
  - Status reported via `gateway_maintenance`.
