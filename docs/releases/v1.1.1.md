# Release Notes: MCP-Pi Gateway v1.1.1

**Release Date:** September 2026  
**Type:** Patch Release — Tunnel Auth Wiring & Authentication Trust Boundary Alignment  
**Status:** PASS  

---

## 1. Summary

MCP-Pi Gateway `v1.1.1` is a focused patch release that resolves upstream Secure MCP Tunnel header resolution wiring, eliminates header collisions with external authorization forwarders, aligns local gateway authentication trust boundaries, and audits credential least-privilege permissions.

All security negative vectors remain strictly fail-closed, with zero arbitrary shell execution, zero open ingress ports, and strict loopback confinement.

---

## 2. Key Highlights & Changes Included

### Secure MCP Tunnel Header Wiring Discovery & Alignment
- **Upstream Tunnel Client Parsing Discovery**:
  - Upstream `openai/tunnel-client` (`3b706ea54d0ad303c85d5ccd35633ae69405570b`) in `pkg/runtimeconfig/config.go` (`resolveHeaderValue`) checks strictly `strings.HasPrefix(lower, "file:")` or `strings.HasPrefix(lower, "env:")`.
  - Passing `Authorization: Bearer file:/path` failed upstream resolution because it starts with `"bearer "`, causing the literal string `"Bearer file:/path"` to be transmitted.
  - Furthermore, upstream `ForwardingRoundTripper` in `pkg/mcpclient/internal/roundtripper.go` overwrites incoming request headers with external remote connector headers. Using `Authorization` risked deletion or overwrite of local static appliance tokens.
- **Dedicated Gateway Auth Header**:
  - Standardized on `X-MCP-Gateway-Auth: file:/home/mcp-gateway/.config/mcp-gateway/tunnel-mcp.token` in `tunnel.env` and `tunnel.env.example`.
  - Enables correct upstream file resolution while preventing clobbering by external remote authorization forwarders.

### Dual-Header Authentication & Anti-Spoofing Hardening
- **Adapter Header Validation**:
  - `mcp-adapter/server.go` implements `ValidateToken` supporting:
    - Primary: `X-MCP-Gateway-Auth` (with or without `Bearer ` prefix).
    - Secondary/Compat: `Authorization` (with or without `Bearer ` prefix).
    - Constant-time verification (`subtle.ConstantTimeCompare`).
  - **Anti-Spoofing**: Asserting `X-MCP-Client-ID` without valid token returns `HTTP 401 Unauthorized: CLIENT_ID_SPOOFING_DENIED`.
  - **Invalid Token**: Returns `HTTP 401 Unauthorized: INVALID_AUTH_TOKEN`.
  - **Anonymous Callers**: Confined to empty catalog (`tools: []`) on list and denied on call.
  - **Header Coexistence**: Gateway correctly authenticates local client via `X-MCP-Gateway-Auth` while safely passing through remote end-user `Authorization` tokens.

### Token Storage Least-Privilege Verification
- Verified real filesystem permissions on MCP-Pi:
  - Configuration directory: `/home/mcp-gateway/.config/mcp-gateway` (`drwx------` / `0700 mcp-gateway:mcp-gateway`).
  - Appliance token: `/home/mcp-gateway/.config/mcp-gateway/tunnel-mcp.token` (`-rw-------` / `0600 mcp-gateway:mcp-gateway`).
  - Admin secret: `/home/mcp-gateway/.config/mcp-gateway/admin-secret` (`-rw-------` / `0600 mcp-gateway:mcp-gateway`).
  - Readable only by `mcp-gateway` and root; strictly inaccessible to unauthorized local users.
