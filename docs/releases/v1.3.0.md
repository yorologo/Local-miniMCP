# MCP-Pi Gateway 1.3.0

> Release identity is the immutable `v1.3.0` tag on `main`. The tag target is the authoritative release commit; runtime `.deployed-git-sha` and `.deployment.json` record the deployed commit.

## Scope

1.3.0 strengthens security boundaries, observability, deployment reproducibility and release usability without changing the Core/Bridge/Registry contract versions.

Key additions include:

- 21-tool catalog v3 with trusted Target shell and structured filesystem tools;
- independent `writes_enabled` and `shell_enabled` controls;
- remote canonical-path enforcement for structured mutations;
- fail-closed audit requirements for critical mutation;
- Target Environment Facts and MCP Tool Annotations;
- exact-commit deployment provenance + transactional rollback;
- generic Admin runtime configuration through private `admin.env`;
- user-facing installer/reinstaller/rollback contract;
- prebuilt-ARMv6 release bundle flow;
- minimal Admin setup bootstrap;
- consolidated CURRENT documentation with semantic drift gate;
- resumable long-job execution with durable state, locking and explicit verification markers;
- idempotent exact-SHA deployment that safely returns `ALREADY_DEPLOYED` for an already healthy verified commit.

## Release acceptance

The final release commit is acceptable only when all applicable local/CI gates, ARMv6 bundle preflight, rollback/deployment acceptance, production Doctor/endpoints/Target/provenance and documentation audit pass on the same SHA.

The immutable `v1.3.0` tag target is the accepted release SHA. Do not duplicate that SHA in prose; use `git rev-parse 'v1.3.0^{commit}'` or the runtime provenance files as the source of truth.
