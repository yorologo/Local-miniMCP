# Release Notes: MCP-Pi Gateway v1.2.0

**Release Date:** September 2026  
**Type:** Minor Feature Release — Dynamic Target Endpoint Resolution & Cryptographic Discovery  
**Status:** PASS  

---

## 1. Summary

MCP-Pi Gateway `v1.2.0` introduces autonomous, zero-configuration dynamic IP target endpoint resolution and cryptographic identity verification across network transitions (such as router reboots, DHCP renewals, and IP reassignment) without relying on MAC addresses, static DHCP reservations, mDNS/Avahi, or external network discovery daemons.

Under this release:
- **Identidad Inmutable**: `TARGET_ID + SSH HOST PUBLIC KEY PINNING`
- **Endpoint Mutable**: `IP + TCP PORT`

The SQLite Registry (`targets.host`, `targets.port`) is established as the **single source of truth** for endpoints, overriding local static OpenSSH configuration while preserving client key identities and enforcing strict host key checking (`StrictHostKeyChecking=yes`).

---

## 2. Key Highlights & Changes

### Dynamic IP Target Resolution & Cryptographic Discovery Engine
- **Single Authority over Endpoints**:
  - `SSHTransport` injects explicit command-line parameters `-o HostName={host} -o Port={port} -o HostKeyAlias={target_id}` before the OpenSSH alias.
  - Command-line parameters override any static `HostName` or `Port` in `~/.ssh/config` from left-to-right, eliminating configuration drift and ensuring SQLite is the sole endpoint authority.
- **Tiered On-Demand Discovery Architecture**:
  1. *Fast Path*: Direct connection to current `targets.host` (zero discovery overhead; ~0.878s total latency).
  2. *Fast Discovery*: Reads kernel neighbor cache (`/proc/net/arp` / `ip neigh`) in < 2 ms; probes candidate target ports with lightweight concurrent socket checks.
  3. *Fallback Discovery*: Dynamically inspects active IPv4 LAN subnets (e.g. `/22` or `/24` without hardcoded prefixes); sweeps target port across unexamined hosts via concurrent thread pool.
  4. *Multi-Key Host Verification*: Invokes `ssh-keyscan` across ED25519, ECDSA, and RSA key types; matches offered public keys against pinned entries in `known_hosts` for `target_id`.
  5. *Atomic Registry Mutation & Single Retry*: Updates SQLite `targets.host` via atomic parameterized SQL, records an audit event in `activity`, and retries the SSH command exactly once (`is_retry=True`).
  6. *Storm Protection*: Per-target re-entrancy locks (`threading.Lock`) and a 20-second cooldown prevent duplicate or runaway network scans.

### DHCP IP Reuse & `ENDPOINT_IDENTITY_MISMATCH` Classification
- **Classification Distinction**:
  - Differentiates between authentic target key rotation (an administrative operation that must never happen silently) and DHCP IP reuse by a foreign machine.
  - When a stored endpoint returns `Host key verification failed` or `REMOTE HOST IDENTIFICATION HAS CHANGED`, it is classified as `ENDPOINT_IDENTITY_MISMATCH`:
    1. Foreign occupant of the old IP is immediately rejected; its host key is never stored, accepted, or trusted.
    2. Discovery is permitted to search for the canonical pinned key on other network endpoints.
    3. If exactly 1 candidate matches the pinned key: `IDENTITY_MATCH` -> Registry updated -> command retried once.
    4. If 0 candidates match: `TARGET_NOT_FOUND` -> fail-closed (no mutation).
    5. If >1 candidates match: `AMBIGUOUS_TARGET_IDENTITY` -> fail-closed (no mutation).
- **Authentication Failures Remain Strictly Fail-Closed**:
  - Failures such as `Permission denied (publickey)` or `Authentication failed` never trigger discovery, preventing erroneous network scans when the target IP is correct but credentials fail.

   - Simulated real 81.9-second LAN/Wi-Fi outage on MCP-Pi (`wlan0` link down).
   - Zero database corruption, zero unauthorized key acceptance, zero scan storms.
   - Upon network restoration, MCP-Pi Wi-Fi re-established automatically (SSH ready in 2.93 s).
   - Gateway `target_status` restored in 1.17 s (Fast Path, 0 ms discovery).
4. **Controlled MCP-Pi Reboot Test:**
   - Issued `sudo reboot` on MCP-Pi. Hardware reboot and Wi-Fi link restored in 208.1 s; SSH fully operational in 244.6 s.
