# Release Notes: MCP-Pi Gateway v1.2.1

**Release Date:** September 2026  
**Type:** Patch Release — Secure MCP Tunnel Production Integration & Deterministic Readiness  
**Status:** PASS  

---

## 1. Summary

MCP-Pi Gateway `v1.2.1` is an operational patch release that hardens daemon lifecycle management and transient dependency auto-recovery for the official **OpenAI Secure MCP Tunnel** (`openai-tunnel-client`) on Raspberry Pi Model A+ (ARMv6, Debian 13 Trixie).

This release resolves the boot order race defect (`BOOT_ORDER_DEFECT`), decouples permanent product gates from transient socket startup wait, fixes curl status parsing, and guarantees fully automatic self-recovery after reboot and during delayed backend availability without manual intervention.

---

## 2. Key Highlights & Operational Fixes

### A. Secure MCP Tunnel Production Integration
- Standardized `openai-tunnel-client` systemd service definition and preflight check script as version-controlled sources of truth in `config/systemd/`.
- Zero runtime configuration drift between repository and production appliance.

### B. Boot Order Race Defect Fix (`BOOT_ORDER_DEFECT`)
- In production reboot scenarios, the tunnel daemon previously attempted immediate startup before the MCP HTTP backend (`http://127.0.0.1:8090/live`) was fully initialized, leading to crash or skipped states.
- Implemented deterministic readiness synchronization: the tunnel daemon now explicitly waits for HTTP 200 from the backend before launching.

### C. Product Gate vs Transient Readiness Decoupling
- **`ExecCondition` (`mcp-gateway-tunnel-check credentials`)**:
  - Validates `CONTROL_PLANE_TUNNEL_ID` and `CONTROL_PLANE_API_KEY`.
  - If missing: exits with code `2` (`OPENAI_PRODUCT_GATE_PENDING`). In systemd, this cleanly marks the unit as skipped (`Result=success`, `NRestarts=0`), preventing infinite restart loops.
- **`ExecStartPre` (`mcp-gateway-tunnel-check backend`)**:
  - Actively polls `http://127.0.0.1:8090/live` until ready or timeout (`120s`).
  - If timeout: exits with code `1` (`MCP_BACKEND_NOT_READY_TIMEOUT`), triggering systemd's `Restart=on-failure` every 15 seconds (`RestartSec=15s`).
  - Corrected curl HTTP status parsing to ensure clean `000` status on connection failure, avoiding `000000` concatenation.

### D. Delayed Backend Auto-Recovery (Empirical Test C PASS)
- Empirically proved on live Raspberry Pi hardware: when the backend socket appears with delay, systemd retries automatically and transitions cleanly to `active (running)` without any manual restart commands.
